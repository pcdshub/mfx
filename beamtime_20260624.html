    MFX Beamtime: K-Scan Commissioning & Wolter First Light

    Dates: June 24, 26, & 27, 2026 (6 AM – 6 PM, 10 Hz secondary program)
    Samples: Fe foil, ferricyanide (K4[Fe(CN)6])
    Spectrometers: 6x von Hamos (cylindrical, Fe Ka), FEE spectrometer, SEER
    Constraints: No vernier moves (primary 120 Hz program on another instrument). TFS locked out.

    Code changes (2026-06-26 evening): - k_xas_scan now prints total elapsed time and time per point at scan completion - New k_move_mode='concurrent_settled' — DAQ stays running but blocks until undulator move returns before stepping DCCM - dwell_time acts as minimum acquisition time in concurrent_settled mode — if the K move takes longer than dwell, no extra wait is added; if shorter, only the remainder is waited - New track_feespec_blocking=False option — FEE spectrometer moves fire non-blocking and overlap with the K move (reduces dead time when spec motion is slow) - FEE camera PV updated: CAMR:FEE1:441:Acquire → XRT:ZYLA:CAM:01:Acquire (Zyla replacement)

    1.2 concurrent_settled Mode Commissioning

    What it is: DAQ stays running (no pause/resume overhead) but the scan blocks on the undulator move — DCCM stepping and dwell timer only begin after the undulator reports settled. Best of both worlds: no DAQ restart dead-time, no data collected during undulator transit.

    Why: In concurrent mode, early DCCM points are collected while the undulator is still moving. In pause mode, the DAQ stop/start adds overhead. concurrent_settled eliminates both issues — clean data at every point with minimal dead-time.

    Mode DAQ during K move Dwell starts after Dwell behavior Overhead
    pause Stopped DAQ restart (~1–2 s) Full dwell added after move DAQ stop + restart + dwell
    concurrent Running Immediately (transit data) Full dwell added after move Dwell only (but noisy early points)
    concurrent_settled Running Undulator settled Minimum — only waits remainder if move < dwell max(move_time, dwell) total

    1.3 Production EXAFS Command (K=16, 3 s/point)

    This is the exact command to run. Works with or without Fe foil — just change sample.

    from mfx.exafs import EXAFSEnergyRangeBuilder

builder = EXAFSEnergyRangeBuilder()
energies, _, _, _ = builder.build_energy_range(
    min_K_value=2.0, max_K_value=16.0, K_spacing=0.5
)

summary = exafs.k_xas_scan(
    k_positions=energies,
    dccm_offsets=[0.0],
    dwell_time=3.0,
    k_move_mode='concurrent_settled',
    track_feespec=True,
    track_feespec_cam=True,
    track_feespec_blocking=False,
    record=True,
    sample='Fe_foil'
)

    Change sample='ferricyanide' for solution runs. Everything else stays the same.

    What this does: - 80 energy points from pre-edge through K=16 (7055–8105 eV, dk=0.5) - concurrent_settled: DAQ stays running, blocks until undulator settles, then counts - 3 s minimum dwell per point — if the K move takes longer (4–5 s), no extra wait is added - FEE spectrometer tracks (non-blocking) — moves in parallel with undulator - Estimated wall-clock: ~80 × max(~4.5 s move, 3 s dwell) ≈ 6 min

    Copy the timing output to the eLog after each scan.

    Key behavior notes: - dwell_time=3.0 is a minimum acquisition time — if the K move takes 4 s, total is 4 s (no extra wait). If move takes 2 s, waits 1 s more for 3 s total. - track_feespec_blocking=False fires the spectrometer motors in parallel with the undulator move — saves ~1–2 s per step. Safety check still runs after K settles.

    2.4 Key Questions for EXAFS (2–4 PM)

    The shift 1 discovery means XANES is fast (4.5s dead-time), but EXAFS steps are 9–120 eV — almost certainly triggering the slow encoder mode (30–45s). The 2–4 PM slot will characterize:

    1. What is the actual dead-time for steps > 5 eV?
    2. Does concurrent mode produce usable data during the longer transit?
    3. Is there a step-size threshold where encoder mode switches?

    7.1 k_xas_scan Flow Diagram

    k_xas_scan()
│
├─ 1. Compute K positions
│     ├─ From start/end/step (uniform)
│     └─ OR from k_positions array (custom)
│
├─ 2. Compute DCCM offsets
│     ├─ From window/step (auto)
│     └─ OR from dccm_offsets list (custom)
│
├─ 3. Store initial positions (for restore)
│
└─ 4. For each run:
     ├─ Setup DAQ (record if enabled)
     │
     └─ For each K position:
         │
         ├─── [pause mode] ─────────────────────────────────────┐
         │    1. Pause DAQ                                       │
         │    2. Move FEE spec → target θ, 2θ, Y                │
         │    3. Move K (undulator)                              │
         │    4. Fine-tune FEE spec crystal angle                │
         │    5. Resume DAQ                                      │
         │                                                       │
         ├─── [concurrent mode] ────────────────────────────────┐
         │    1. Move FEE spec                                   │
         │    2. Request K move (non-blocking)                   │
         │    3. Begin DCCM stepping immediately                 │
         │                                                       │
         └─ For each DCCM offset:
              ├─ Move DCCM to (K + offset) / 1000 keV
              │   └─ Crystal only — NO vernier!
              ├─ Check beam (if flux_threshold set)
              ├─ Dwell (collect data)
              └─ Record summary point
     │
     └─ Return to initial positions

    Key constraint: DCCM moves are crystal-only (self.dccm.energy.move()). No vernier PV is touched. This is critical for 10 Hz secondary program operation.

    8. XRT Spectrometer Tracking

    8.1 Overview

    The XRT spectrometer (XRTspec in mfx/xrt_spec.py) is a Si(111) Bragg spectrometer in the FEE (Front-End Enclosure). It diffracts from the transmitted beam upstream of the hutch and provides a shot-by-shot measurement of the incident photon energy spectrum.

    Why it matters: During a K scan the undulator changes energy at each step. The XRT spectrometer must track so that the diffracted beam stays on its camera. Without tracking, the Bragg condition is no longer satisfied and the spectrometer sees nothing.

    8.2 Tracking Sequence

    Step Function What it does
    1 move_feespec_energy(E) Full repositioning (theta, 2-theta, camera Y)
    2 check_feespec_crystal_angle(E) Fine correction after K settles

    move_feespec_energy(E) details:

    1. Stop camera acquisition (avoid motion blur)
2. Store current positions (rollback reference)
3. Compute targets via get_feespec_positions()
4. Move crystal angle (θ), camera angle (2θ), camera Y
5. Check XRT transmission alarm
   └─ If alarm → rollback to stored positions

    check_feespec_crystal_angle(E) details:

    1. Compare current θ to calculated target
2. Only move if difference > 0.01°
3. Restart camera acquisition
4. Check XRT transmission alarm

    8.3 Calibration Formulas

    Empirical calibration for Si(111) at MFX (in mfx/xrt_spec.py):

    Axis Formula Units
    Crystal angle (theta) 140.08 - 21.2*E + 1.02*E^2 degrees
    Camera angle (2-theta) -1.91 + 2*theta degrees
    Camera Y -4.92 - 0.111*E mm

    where E is photon energy in keV (e.g. 7.112 for Fe K-edge).

    8.4 crystal_angle_offset

    Property Value
    What it shifts Crystal angle only (not camera angle or Y)
    Effect Moves where diffracted line lands on camera
    Positive value Increases crystal angle
    Default 0.0
    Adjust via Recipe 6 (empirical)

    8.5 Safety: XRT Transmission Alarm

    After every move, the code reads XRT:HXS:TRNS.SEVR:

    Alarm state Action
    NO_ALARM Continue normally
    Any other severity Rollback — return to previous position

    This prevents the crystal from blocking the beam or scattering into optics in a bad configuration.

    11.2 k_xas_scan Method

    File: mfx/exafs.py | Line: L1696

    K-primary scanning mode where the undulator is the primary axis and DCCM tiles around each K position.

    Feature Description
    No vernier requests Uses dccm.energy (crystal only), safe for secondary program
    Three K move modes 'pause' (stop DAQ, move, resume), 'concurrent' (move during collection), 'concurrent_settled' (DAQ running, block on move)
    Minimum-dwell logic In concurrent_settled: dwell_time is a floor, not additive. Total = max(move_time, dwell)
    Non-blocking FEE spec track_feespec_blocking=False overlaps spectrometer motion with K move
    Custom K positions Pass k_positions=array for non-uniform spacing
    DCCM window Configurable offsets around each K center
    FEE spec tracking Moves spectrometer crystal at each K step (XRTspec)
    Elapsed time logging Prints total elapsed + time/point at scan end (copy to eLog)
